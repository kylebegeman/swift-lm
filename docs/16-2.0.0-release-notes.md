# SwiftLM 2.0.0 Release Notes

## Audience

SwiftLM 2.0.0 is for Swift app developers building local-first or explicit-provider language model features on Apple platforms, including the OS 27 releases.

This is a major release. It renames the package and every public type prefix, adopts the OS 27 Foundation Models framework behind an SDK gate, and fixes the correctness issues found in a full audit of the core, the Foundation Models adapter, and the OpenAI and Anthropic adapters.

## Rename

The package is `swift-lm`. The library handles language models of every size, so the name no longer says "large".

| 1.x | 2.0 |
|---|---|
| `swift-llm` | `swift-lm` |
| `SwiftLLM`, `SwiftLLMFoundationModels`, `SwiftLLMOpenAI`, `SwiftLLMAnthropic`, `SwiftLLMEvaluation` | `SwiftLM`, `SwiftLMFoundationModels`, `SwiftLMOpenAI`, `SwiftLMAnthropic`, `SwiftLMEvaluation` |
| `LLMClient`, `AnyLLMClient`, `LLMRequest`, `LLMResponse`, `LLMRouter`, and every other `LLM*` type | `LMClient`, `AnyLMClient`, `LMRequest`, `LMResponse`, `LMRouter`, and every other `LM*` type |
| `LLMShowcase` | `LMShowcase` |
| `LLMToolChoice.none` | `LMToolChoice.noTools` |

A mechanical migration in an adopting app is two replacements: `SwiftLLM` to `SwiftLM`, then `LLM` followed by an uppercase letter to `LM`. Prose that says "LLM" is unaffected.

## OS 27 Foundation Models

Apple's Foundation Models framework in the OS 27 releases adds Private Cloud Compute, a `LanguageModel` protocol, reasoning levels, usage reporting, tool calling modes, and a new error taxonomy, and deprecates `GenerationOptions(sampling:)` and `LanguageModelSession.GenerationError`. SwiftLM 2.0 adopts all of it in `SwiftLMFoundationModels`:

- `FoundationModelExecutionTarget.privateCloudCompute` runs requests on Apple's server model. `automatic` still resolves to the on-device model, because the package is local-first.
- `FoundationModelClient.availability(for:)` reports Private Cloud Compute eligibility, readiness, locale support, and quota exhaustion.
- `FoundationModelClient.runtimeProfile(for:)` reports the platform context window (`contextSize`), capability flags, and quota status. Provider-neutral capabilities and context budgets follow it.
- `LMGenerationParameters.reasoningEffort` maps to Apple's light, moderate, and deep reasoning levels. On-device requests that ask for reasoning are rejected as unsupported so routers can fall back instead of silently ignoring the request.
- Token usage comes from Apple's usage reports, including cached input tokens and reasoning tokens, and reasoning text is captured from the transcript.
- Quota exhaustion, network failures, service unavailability, timeouts, and unsupported capabilities map to `FoundationModelFailure` reasons and to `FallbackReason.quotaExceeded`, `unavailable`, `timeout`, and `unsupported`.
- Native streaming through `FoundationModelClient.stream(_:)` on every supported release.
- Multi-turn provider-neutral requests are replayed as a real transcript, and `FoundationModelSession` keeps one conversation, its key-value cache, and its native tools across turns.
- `FoundationModelClient.live(model:executionTarget:contextWindowTokens:)` runs any OS 27 `LanguageModel`, such as a Core AI or MLX model or a provider package, with the same routing, receipts, and error handling as Apple's models.
- Images attach to user messages through `LMImage`. On the OS 27 releases they reach models that accept images as prompt attachments; OpenAI and Anthropic receive them in their native formats.

The OS 27 symbols compile only with the OS 27 SDKs, which ship with Xcode 27 and Swift 6.4. The gate is `#if compiler(>=6.4) && !SWIFTLM_OS26_SDK_ONLY` plus runtime `#available` checks, so the package still builds with Xcode 26 and still runs on OS 26 devices. Apps built with Xcode 27 receive the new error types on OS 27 devices and the OS 26 error types on OS 26 devices; both are normalized.

Private Cloud Compute needs the managed entitlement from Apple, a device that supports Apple Intelligence, and a network connection, and each person has a daily request quota. Read `FoundationModelQuotaStatus` from the runtime profile and show persistent usage UI rather than a dismissible alert.

## Provider Adapters

The audit found that live streaming never delivered incrementally for either provider: the parser waited for blank SSE separator lines that `URLSession` line streams omit. Both adapters now dispatch each `data:` line as it arrives.

Current Claude and GPT reasoning models reject `temperature` and `top_p`. Both adapters now derive `acceptsSamplingParameters` from the model family, drop the matching capabilities, and reject such requests before sending them, so routers skip the client instead of failing mid-request. Override the flag when a model does not follow its family.

Reasoning models require their reasoning items or thinking blocks to be replayed with tool results. `LMMessage.providerContent` stores that provider-native payload on the response message and replays it on the next turn.

OpenAI: the Responses API has no `stop` parameter, so stop sequences are no longer sent or advertised. Responses are not stored server-side unless `storesResponses` is set. Refusals throw `guardrailViolation`, incomplete responses report `length` or `contentFilter`, and error codes such as `insufficient_quota` and `context_length_exceeded` map to typed reasons.

Anthropic: strict JSON schemas use native structured output, thinking is adaptive with an effort level when `reasoningEffort` is set, prompt caching and strict tool schemas are opt-in, and `refusal` stop reasons throw `guardrailViolation`. The default `max_tokens` is 8,192 because thinking counts toward it.

## Core Fixes

- `LMStep.repairOrFallback` no longer returns a rejected candidate as the workflow output.
- `StructuredGenerationPipeline.run` rethrows cancellation instead of recording a fallback.
- Workflow failures throw `LMWorkflowError` with the accumulated diagnostics.
- `TextChunker` can no longer degrade to a one-word stride when the overlap is large.
- `LMEndpointRegistry.router(primaryID:)` keeps fallbacks explicit; a local-only primary never escalates to a cloud endpoint unless asked.
- `LocalDebugBundle` enforces redaction instead of labeling it.
- Streaming routes emit run receipts, and network errors classify as retryable.

## Known Limitations

- The OS 27 code path has been compiled and tested on GitHub's Xcode 27.0 beta image, but not yet run on a device with Private Cloud Compute access. Exercise a Private Cloud Compute feature on a device before shipping it.
- Dynamic Profiles are not wrapped. Use Apple's API directly, or compose `LMWorkflow` steps that call different clients.
- SwiftLM consumes `LanguageModel` providers but does not publish its OpenAI and Anthropic clients as `LanguageModel` providers. Use the providers' own Foundation Models packages for that.
- Foundation Models accepts images only in the latest user message, and provider-neutral Foundation Models requests cannot replay tool calls from earlier turns. Use `FoundationModelSession` for conversations with native tools.
- Transcript compaction remains an app concern.
- Model-family rules for OpenAI and Anthropic are tables inside the adapters. Update them as providers change model behavior.

## Validation Summary

Validated locally on September 16, 2026 with Swift 6.3.3 and the OS 26.5 SDKs:

- `swift build -Xswiftc -warnings-as-errors`
- `swift test` (97 tests across 16 suites)
- `./scripts/validate.sh`, including the showcase build for the iOS Simulator with Xcode 26.6 before the final Anthropic model-family refinements, which do not touch the showcase
- the final tree with Command Line Tools 26.6, where the script skips the showcase build
- a scratch build of `SwiftLMFoundationModels` with the OS 27 gate forced on against a stub of the documented OS 27 API

CI adds a job on GitHub's `xcode-27` preview image, which compiles the gated code against the OS 27 SDKs from an Xcode 27 beta. Tag 2.0.0 after that job and a local Xcode 27 build both pass.
